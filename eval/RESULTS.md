# Extraction and scoring eval

Generated by `npm run eval`. Do not edit by hand: the numbers come from replaying stored model responses through the shipped pipeline.

## What this measures

Ledger makes a regulatory claim from a photograph, so the question this harness exists to answer is how often it is right. The answer comes in two halves, and they must not be added together.

**Extraction accuracy** is how well the vision model reads a photographed order record. It can only be measured from responses recorded from a real model run against the fixture images.

**Pipeline conformance** is how well everything after the model behaves: the pack and quantity parsers, the storage override, the accessory rules, the partition step, the stocking standard and the scorecard. It is measured by feeding the pipeline a response derived from the fixture itself, so the transcription is correct by construction and any error that shows up belongs to our code.

## Fixtures

- 24 order records, 24 of them synthetic.
- 319 line items with hand-labelled ground truth: category, variety, storage, units per pack, packs, and whether the line can be counted at all.
- Expected verdicts come from `eval/reference-scoring.mjs`, a second implementation of the stocking standard written from the rule rather than from the app, and are committed as literals on each record.
- **Every fixture is synthetic.** No real store's order record is in this repository. `eval/README.md` sets out what that costs these numbers.

## 1. Extraction accuracy (the model)

**Not measured.**

There are 24 stored responses and none of them is a recording of a real model run, so this section has no data. Nothing in this repository reports how often the vision model reads an order record correctly, and the README says so too.

To measure it, with an `OPENROUTER_API_KEY`:

```bash
npm run eval:images   # render the fixture images (needs Chromium)
npm run eval:live     # call the model on each one and record what it says
```

That writes `source: "recorded"` responses into `eval/responses/`, and this section fills in on the next run.

## What these numbers cannot tell you

- Whether the model reads real handwriting, real glare or a real dot-matrix printer. The images are drawn from HTML, and the hand-written ones simulate an irregular hand rather than photographing one.
- Whether the order record reflects what is on the shelf. The eval scores the record, and so does the app.
- Whether USDA would classify these products or varieties the same way. The category and perishable labels here are our reading of the rule.
- Anything about Criterion B, specialty-store treatment, or authorisation itself.
